# Architecture — model-logos → full DSH icon plugin (v0.2)

> **Toolchain note (v0.3).** The build was migrated from hand-written `.mjs`/`.js`
> fragments concatenated by a regex script to a typed TypeScript module graph
> bundled by esbuild, with Vitest/oxlint/oxfmt. `docs/engineering.md` is the
> current contract: module map, commands and conventions. Module paths below are
> the historical ones — the shipped sources are now `src/*.ts` (for example
> `src/match.ts`, `src/logos/cn.ts`, `src/label.js` → `src/client.ts`,
> `index.js` → `src/host.ts`), and the build script is `scripts/build.ts`.

Working design note for the current upgrade. It records the runtime facts taken from
the shipped DSH packages (read out of `app.asar`), the decisions confirmed with the
user, the file ownership split, and the exact interfaces every contributor codes
against.

## 1. Goal (user-approved)

Upgrade `dsh-model-logos` from "composer-only model marks" to a full DSH icon plugin:

1. **Settings → Models, provider list**: show the vendor (厂商) logo left of every
   _official catalog channel_ row name, sized to the text. Hand-declared
   (custom) providers get no vendor logo.
2. **Settings → Models, add-provider dropdown**: every option of the provider
   `<select>` shows its vendor logo.
3. **Settings → Models, provider editor model rows**: show the model (模型) logo
   left of each model configuration row.
4. **Refactor model-icon resolution**: heuristics only pick the _initial_ icon.
   A popup icon picker lets the user override it per `provider + model`, so local /
   exotic models also get an icon. Overrides are persisted in the DSH user settings
   document (profile `cordis.patch.yml`), not in localStorage.

Also: the existing composer model label (`conversation.input.model.label`) keeps
working and now honours the same overrides. Distinguish **vendor logo** (the
channel/brand that serves models) from **model logo** (the brand of the model).

Confirmed answers:

- Picker entry: click the logo on a Settings → Models model row **and** a
  dedicated "Model icons" settings section for the complete list.
- Persistence: DSH user settings document (host plugin `Config` with a volatile
  field) → written into the profile's `cordis.patch.yml`.
- Vendor coverage: reuse existing artwork + add common brands + deterministic
  letter-tile fallback for obscure official channels.
- Scope: settings → models three places + existing composer selector. `/model`
  command popup rows stay unchanged.
- Add-provider select: custom combobox painted over the native `<select>` (the
  native select stays the state source; options cannot hold images).

## 2. Current plugin (v0.1) — what stays

- `src/match.ts`: ordered provider/model heuristic → logo key. Keep, extend.
- `src/logos/official.generated.ts` / `src/logos/manual.ts`: official vector tiles plus
  the documented manual exceptions (formerly hand-drawn sets in `intl.ts` / `cn.ts`).
- `src/client.ts`: the `conversation.input.model.label` contribution (priority −1,
  reproduces the shipped 1017 badge).
- `client.js`: generated by `scripts/build.ts` (esbuild); never edit by hand.
- `scripts/verify-live.ts`: proves the running GUI serves this exact build.
- `src/host.ts` → generated `index.js` (host half).
- `cordis.patch.yml`: inserts host entry `id: dsh-model-logos`, `name: dsh-model-logos`.

## 3. Runtime facts taken from the shipped app (app.asar)

### 3.1 Settings → Models DOM

Package `@deepseek-ai/dsh-client-ui-settings-models` (`lib/client.js`, readable —

`[data-shortcut-modal="settings"]` and `role="dialog"`. Only the active section is

### 3.2 Provider directory and model sources

Client services available to any browser plugin (cordis service injection):
`slots`, `locale`, `remote`, `remote.llm`, `remote.settings`, `configForms`,
`theme`, `connection` …

- `ctx.remote.llm.listConfigurableProviders()` → `[{ provider, displayName,
  settingsNs, settingsPath, declared?, defaultBaseURL?, baseURLEnv?, nativeAuth? }]`.
  `declared === true` means a hand-declared (custom) route → **no vendor logo**.
  This is the official channel directory (pi-ai catalog + llm-deepseek).
  The exact service key must be injected (`ctx.inject(['remote.llm'], …)`); reading
  `remote.llm` from a context that only injected `remote` throws
  `cannot get property "remote.llm" without inject`.
- `ctx.remote.llm.listProviders()` → live adapter routes `{ id, name }`; routes not
  in the directory (e.g. `deepseek-account`) are also official.
- `ctx.configForms.describe()` → mirror over the settings document:
  `snapshot.view.namespaces: [{ ns, schema, value, base, user, revision }]`.
  Model catalogs live in the user settings values of `llm-pi-ai`
  (`providers[*].models[*]`) and `llm-deepseek` (`models[*]`).
- `ctx.configForms.get(entryId)` → form controller: `getSnapshot()` =
  `{ status, value, base, user, revision, writable }`, `subscribe(fn)`,
  `set(field, value)`, `unset(field)`, `mutate(ops, expectedRevision?)`.

### 3.3 Settings persistence (native)

A host plugin becomes a settings namespace by exporting a schemastery `Config`
whose field carries `.volatile()`. The Host projects that field through
`settings.describe`; writes land in the profile's `cordis.patch.yml` under the
entry `id`. Exactly how `ui-settings-general` stores `welcomeNoticeVersion`.

Our host half (`index.js`):

```js
import z from '@deepseek-ai/schemastery';

export const Config = z.object({
  modelIcons: z.dict(z.dict(z.string())).volatile(), // providerId → modelId → icon key
});

export function apply() {}
```

Namespace / entry id: **`dsh-model-logos`** (from `cordis.patch.yml`).
Client reads/writes it through `configForms.get('dsh-model-logos')`:

- set: `form.mutate([{ op: 'set', path: ['modelIcons', providerId, modelId], value: key }])`
- clear: `form.mutate([{ op: 'unset', path: ['modelIcons', providerId, modelId] }])`
- value sentinel `'none'` = user explicitly disabled the icon. Absent = auto
  (heuristic initial icon).
- `@deepseek-ai/schemastery` must be a real dependency of the plugin (the host
  imports it; a linked local install needs `pnpm install` in this repo).

Note: the host half is loaded at Host start / plugin reload. Changing `index.js`
requires the plugin entry to be reloaded (plugin manager toggle or app restart);
the browser half hot-reloads through the existing HMR transport.

### 3.5 Slots

- `conversation.input.model.label` — `single`, owner props
  `{ provider: { id, name }, model, placement: 'trigger'|'menu'|'option' }`.
  Current contribution at priority −1 shadows the shipped 1017 label; keep.
- `settings.section` — `list`; register with
  `ctx.slots.register({ name: 'settings.section', id: 'model-logos', order, label: () => text }, Component)`.
  Our section appears in the Settings navigation next to Models.
  The slot's register options are only `id` / `order` / `label`: the slot core
  drops any other key, and the shell picks each row's glyph from a hard-coded
  switch over its own section ids (`account`, `models`, `plugins`, …), falling
  back to the settings gear for everyone else — including `model-logos`. The nav
  row therefore carries no section id in the DOM (React's `key` is not
  serialized) and the only signal is the localized row label, which the shell
  re-projects whenever the section ledger or the locale revision changes. The
  row's icon is consequently a decoration, not a registration: `src/nav-icon.ts`
  sets `data-dshml-nav` on the row matched by label and the plugin stylesheet
  hides the gear and paints the plugin glyph as a `currentColor` mask, so React
  re-renders (which rewrite `class`) and theme changes keep working. Replacing
  the whole `sidebar.settings` slot would be the only registration-shaped
  alternative and would mean reimplementing the Settings shell.

## 4. Decisions inside the plugin

- **Vendor logo** is resolved from the provider route id only, via an explicit
  channel table for the official channels (`VENDOR_RULES` in `src/match.ts`).
  Unknown official channels get a deterministic letter tile from the display
  name. Declared custom providers get nothing.
- **Model logo** resolution order:
  1. explicit override in `modelIcons[providerId][modelId]` (`'none'` → no icon);
  2. heuristic (`matchModelLogo`) — this is only the _initial_ icon;
  3. none.
- Icons are inline SVG tiles. Every conversation and Settings mark renders on one
  shared 22px base; the icon picker preview is the single enlarged surface at 36px.
  The composer label's mark is optically nudged 2px down (`position: relative;
  top: 2px`, paint-only): a 13px/20px line's glyphs sit below the centre of its 22px
  mark box, so without the nudge the mark reads high in the 28px composer trigger and
  the model menu instead of on the name's line. Settings → Models reserves that 22px
  in two places from the first decoration pass:
  a mark seat in front of every provider row name / editor title (the vendor mark
  on official channels, empty width on hand-declared providers) and the icon seat at
  the start of every model row (the mark, or the dashed placeholder). Both seats are
  inserted before the async catalog can resolve them, so a mark that renders late
  never moves the row's text.
- The picker offers: auto (heuristic), none, a "letter tile" option generated from
  the model name, and the shipped marks split into **vendor icons** (the company or
  channel) and **model icons** (the model product). Company and model marks are
  separate artwork keys when their official graphics differ (Alibaba vs Qwen,
  Anthropic vs Claude, Google vs Gemini, ByteDance vs Doubao); identical company and
  model marks are listed once in the model group and reused by the vendor channel.
  Both groups are ordered by a checked-in, multi-source prominence snapshot, so the
  list is not alphabetical.
- **Brand names are localized, but only officially.** In the zh locale every
  vendor/model option shows the brand owner's own Chinese name where one exists
  (阿里巴巴, 月之暗面, 千问, 豆包, 蚂蚁百灵, …). A brand with no vendor-published
  Chinese name keeps its official English title; community/fan translations are
  never admitted — `docs/brand-names.md` records the primary source for every
  entry, and `scripts/build.ts` rejects a stale key, a name that duplicates the
  official title, or a "Chinese" name without a CJK character. The picker search
  matches the artwork key, the official title and the localized names in both
  languages, so `通义` no longer finds Qwen (that brand is retired) while `千问`
  and `qwen` both do.
- Artwork is imported from pinned official vector sources by a script and validated
  against the committed upstream files (`logo:check`). The three named corrections
  (Claude, Ollama, Doubao) and the other redraws are source changes, not visual
  guesses; hand-drawn exceptions are limited to marks with no usable official vector
  or no official mark at all.
- Everything is per (provider id, model id), never model id alone.

`apply(ctx)`:

### 6.9 `scripts/build.ts`

- Imports the artwork sets (`src/logos/official.generated.ts`,
  `src/logos/manual.ts`) and validates them: every `LOGO_KEYS` entry has artwork,
  every entry has a vendor/model group and a prominence rank, the groups' ranks are
  contiguous, no duplicate keys across sets, every SVG is self-contained (no `id`,
  script, event handler or external reference), and the vendor tables only reference
  known keys. The `letterTile` fallback is validated too.
- Validates the localized brand-name table in `src/i18n.ts`: every key has
  artwork, every value is a trimmed non-empty string that differs from the official
  artwork title and contains a CJK character (a pure-English "Chinese" entry is a
  mistake, not a translation), and no entry duplicates the English title.
- Bundles `src/client.ts` (esbuild, IIFE, `globalName: __dshml`) into the
  `window.__ModuleLoader__.load({ id, factory(require) { … } })` contract with
  `react`/`react-dom`/`react-dom/client` external, then asserts the contract
  markers are present.
- Bundles `src/host.ts` into `index.js` (esbuild, ESM, schemastery external).
- `--check` rebuilds both artifacts in memory and fails when the on-disk
  `client.js` / `index.js` differ (or are missing), so a local DSH install can
  never silently serve a stale build. The artifacts themselves are generated and
  git-ignored — the repository tracks only the sources.

## 7. Decoration contract (fixture + implementation)

Implementation lives in `src/decorate.js`; the fixture must reproduce the markup
above.

1. **Root**: `document.querySelector('[data-shortcut-modal="settings"]')`. Absent
   → nothing happens. MutationObserver on `document.body` (childList+subtree) and
   a debounced `input`/`change` capture listener keep decorations fresh. The
   observer also disconnects when the plugin disposes. Two invariants keep it from
   observing itself: records whose target sits inside an inserted
   `[data-dshml-owner="1"]` node are ignored (our own writes are output, not page
   state), and every mark/text write is compared against the last value written to
   that node, so a no-op pass performs no DOM write at all — otherwise each pass
   would schedule the next forever and the marks would flash under inspection.
2. **Provider rows / editor titles**: find the provider identity for a leaf element
   whose trimmed text equals a directory `displayName` (plus the documented
   localized aliases), and:
   - its closest `li` exposes `Edit`/`Delete` row actions → saved provider row;
     else, if its parent chain contains an `editorHeader` (element whose text also
     appears in the row actions of the same card) → editor title. Ensure the 22px
     mark seat immediately **before** that text element (a sibling; never
     wrap/rewrite React text nodes).
   - Official channels fill the seat with the vendor mark (set
     `data-dshml-vendor="<providerId>"` on the seat); hand-declared providers get
     no invented mark but keep the empty seat, so rows line up.
   - While the directory is still loading, a saved row name (recognisable from its
     row actions) gets the provisional empty seat, so the name cannot jump when
     the mark arrives.
     Idempotent: a pass reconciles the seat in place and writes only on change.
3. **Model rows**: `input` in the modal whose `aria-label` matches
   `/^(?:Model ID|模型 ?ID|Display name|显示名称)\s+\d+$/` (model id input,
   first column). For its `input.parentElement` (the grid row):
   - resolve `modelId` from the `Model ID` input's `value`;
   - resolve `providerId` from: the enclosing add-card's provider `<select>` value,
     else the enclosing `li`'s provider-name text mapped through the directory,
     else the enclosing setup/editor card title mapped through the directory;
   - insert the model-logo seat (`type=button`) as the first child of the grid row
     from the first decoration pass — even while the provider identity is still
     unresolved, in which case it shows the dashed placeholder. Add
     `data-dshml-model-row` + the CSS grid-template override with an extra `auto`
     column so the seat's 22px is reserved for as long as the row exists;
   - click → re-resolve the identity, then `dshmlOpenIconPicker({ providerId,
     modelId, ... })`;
   - refresh logo when the id input changes (capture `input` listener).
     Idempotent per row; empty model id → no icon.
4. **Custom provider select**: a `<select>` inside the modal whose `option`
   values are all directory provider ids. Hide it in place
   (`position:absolute; opacity:0; pointer-events:none; height:0` — keep it in the
   DOM as the React state source, `tabIndex=-1`, `aria-hidden=true`) and insert a
   custom combobox button + popup menu after it. Menu items show vendor logos.
   Choosing sets `select.value = id` and dispatches `new Event('change',
   { bubbles: true })`; the displayed face also re-syncs on `change` and on
   mutations. Keyboard: Enter/Space/ArrowDown open, arrows move the active item,
   Enter picks, Escape closes.
5. All decoration must be reversible on dispose (remove inserted nodes, restore
   hidden select, disconnect observers/listeners).
